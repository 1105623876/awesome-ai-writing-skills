# Roadmap 构建与 Review 清单

roadmap 在这个 skill 里有双重身份：**动笔前是提纲，写完后是核对清单**。
正文的每一节都应能映射回 roadmap 的一个节点；roadmap 里没有的内容出现在正文里，
要么补进 roadmap（并查证），要么删掉。

## 一、构建 roadmap 并落盘（工作流第 2 步）

调研顺序：原论文 / 教科书 → 官方文档 → 高质量综述（survey）→ 博客（只用于发现线索，不作依据）。

**roadmap 必须写成文件**：`<主题短名>_概念梳理.roadmap.md`，与文档同目录。
理由：长文档写作会填满上下文，review 必须"对文件不对记忆"，否则核对失去对照物。
交付后先保留（它就是文档的可信来源清单，供用户对照检查）；
用户明确说任务完成后，按 SKILL.md 工作流第 8 步连同其他中间产物一并删除。

roadmap 文件至少包含四部分：

### 1. 子概念清单

主题拆成的全部一级节点（方法/概念），每个节点记录：

| 节点 | 一手来源 | 关键公式编号 | 与其他节点的关系 |
|---|---|---|---|
| Momentum | Polyak 1964 / 综述 §2 | 更新式 | SGD 的改进；被 Adam 吸收 |

覆盖度判据：主流教科书/综述都会讲的节点必须在；争议性/小众方法可入"扩展阅读"不展开。

### 2. 演变时间线（如有）

`年份 — 方法 — 驱动缺陷 — 针对性改进`，四元组齐了才算一条。

### 3. 依赖关系

哪些概念必须先讲（如：讲 Adam 前必须先有 Momentum 和 RMSProp 的式子）。
正文顺序必须服从依赖关系——**读者读到任何一个公式时，其全部前置概念都已定义**。

### 4. 每节点的核对材料（最重要）

关键公式**逐条抄录进 roadmap 文件**（含出处编号、链接）+ 史实（年份、作者）。
抄录必须在查证的当下完成，不许事后凭记忆补写；后续一切核对以这份抄录为准。

## 二、Review 的执行方式

review 分两段，不许全文写完后一次性补查（那时上下文最满、查得最松）：

1. **逐节增量核对（写作中）**：每写完一个一级节点，立即对 roadmap 文件过一遍
   清单 B 项。此时错误最便宜、上下文最新。
2. **全局 review（写完后，硬门禁）**：跑清单 A / C / D / E 全局项，
   再做一次 **B 项独立视角复核**（见下）。

### 独立视角复核（必做）

同一上下文里"自己查自己"不可靠——写错的公式会再次看着顺眼。B 项复核必须换干净视角：

- 当前环境支持子代理时，启动一个干净上下文的通用子代理；否则在清空工作假设后重新载入来源，执行独立的第二遍复核。复核者只接收两个输入：
  roadmap 文件（含公式抄录）+ 正文文档路径；
- 任务指令：逐条比对正文编号公式与 roadmap 抄录（系数、符号、上下标、求和范围、期望/求和），
  并对照本文件"常见原则性错误目录"排查；输出问题列表（位置 + 问题 + 依据），**只报告不改文件**；
- 主流程逐条处置：修复 / 有依据地反驳 / 标注存疑；有修复则修复项重查。

可选升级（高风险推导、用户要求高可靠时）：用 model-debate skill 或本机多模型 CLI
（codex / opencode）交叉核对关键推导，分歧点回到一手来源裁决。

### 数值验证（可计算公式，推荐）

"看着对"不如"算着对"。对可数值化的公式，用一次性命令验证特例点，不落盘脚本：

```bash
# 例：Adam 偏差修正，t=1 时应有 m_hat_1 = g_1
python3 -c "b=0.9; g=1.0; m1=(1-b)*g; print(m1/(1-b**1))"   # 期望输出 1.0
```

适用对象：偏差修正/归一化常数（代入特例）、梯度表达式（有限差分对照）、
不等式与非负性（随机点采样）。验证不过 → 公式或抄录有错，回到一手来源裁决。

## 三、Review 清单

全部通过才算完成；任何一项失败 → 修复 → **从该项重新查起**。

### A. 覆盖度（对 roadmap 文件）

- [ ] roadmap 每个一级节点在正文有对应小节（或显式写明"不展开，见扩展阅读"）
- [ ] 正文没有 roadmap 之外的"顺手写上"的内容（有则补查证并补进 roadmap，或删）
- [ ] 章节顺序满足依赖关系，无前向引用未定义概念

### B. 公式逐条核对（最重；写作中逐节执行，全局阶段由独立视角复核）

对正文**每一条**编号公式：

- [ ] 与 roadmap 抄录（即一手来源）逐项比对：系数、符号、上下标、求和范围、是否取期望
- [ ] 量纲/形状一致：等号两边形状相同，累加项同形
- [ ] 特例退化正确（如：Adam 在 $\beta_1{=}\beta_2{=}0$ 时应退化为符号有别的 SGD 变体——退化结果与已知结论矛盾则公式有错）
- [ ] 符号在首次使用前已进符号表，且全文无重载
- [ ] 推导相邻两步之间无隐藏假设；有则显式写出
- [ ] 可数值化的公式已做数值验证（见第二节），验证命令与结果记入交付报告

### C. 史实与归属

- [ ] 年份、提出者、"首次提出"类表述逐条有来源；查不到的删年份、改弱表述
- [ ] 方法名与原论文一致（缩写展开正确）

### D. 逻辑与表述

- [ ] 章节衔接成链：每个方法节的动机写明"承接上一节的什么遗留问题"，一级节之间有过渡句；
      衔接句写的是因果（缺陷 → 改进），不是目录式的"接下来介绍"
- [ ] 每个方法有落地例子（数值代入或贴背景类比），例子演示机制而非复述结论；
      省略例子的节确因机制直白，不是遗漏
- [ ] 优缺点、性质、"实践中表现"类判断句：有公式依据、有引用，或标注为经验/补充
- [ ] 对比表中每个单元格能在正文找到支撑
- [ ] `> 📌 补充：` 标记完整——所有非一手来源内容都已标出

### E. 成品质量

- [ ] 图片相对路径有效；每张图有图注（编号+说明+图源）、每张表有题注；图/表编号各自连续，正文引用与编号一致；assets 无未使用文件（自绘图的生成脚本 `.py` 除外；codex 的 prompt/log 中间产物须已删）
- [ ] 颜色/标注/公式编号写法与目标渲染器一致（见 doc-template.md 第二、三节）
- [ ] 语言过一遍去 AI 味（见 doc-template.md 第五节）

## 四、常见原则性错误目录

review 时对照这份高发错误清单主动排查（不限于此）：

**数学层**
- 卷积与互相关混淆（深度学习框架的 "conv" 实为互相关，不翻转核）
- 期望与经验平均混写（$\mathbb{E}$ 与 $\frac{1}{N}\sum$ 何时可换未说明）
- 梯度与方向导数、Jacobian 与梯度的转置关系写反
- 漏掉偏差修正、归一化常数、正则项系数（如 Adam 的 $\hat{m}_t = m_t/(1-\beta_1^t)$）
- 最大化/最小化目标符号写反（如 log-likelihood vs NLL、KL 的方向 $D_{KL}(P\|Q) \neq D_{KL}(Q\|P)$）
- 上标/下标错位：时间步 $t$ 与层号 $l$ 与样本号 $i$ 混用
- 概率密度与概率混称；连续/离散情形的公式混用

**概念层**
- 把"某论文的特定实现"当成"该方法的定义"
- 把经验现象说成定理（如"Adam 一定比 SGD 快"）
- 因果与相关混淆（"X 方法效果好因为 Y" 需要来源支撑）
- 演变史张冠李戴：改进动机安错对象、时间先后颠倒

**表述层**
- 同一概念前后用不同名字/符号
- 对比表维度与正文结论矛盾
- "优点"和"适用场景"互相打架（前文说省内存、对比表写开销大）
- 章节并列堆叠、互不呼应：下一节不回应上一节的遗留问题，读起来像词条合集而非一条脉络
- 例子只是把结论换句话重说，代入后看不出机制（等于没举）

## 五、交付报告格式

最终回复按此骨架给出，防止"全部通过"一句话敷衍：

```markdown
文档：<路径>（约 N 字 / M 个一级节点）；图片目录：<路径>（K 张）；roadmap：<路径>
公式核对：共 X 条编号公式，逐节核对 X 条；独立复核发现 Y 处问题，已修复 Z 处
数值验证：<验证过的公式与结果；本主题无可数值化公式则写明>
史实核对：X 条年份/归属，来源见 roadmap 文件
存疑/未覆盖：<逐条列出；没有则写"无">
```
