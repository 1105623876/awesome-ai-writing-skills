# concept-well-know：方向/概念梳理文档

把 LLM / Agent / 计算机领域的**一个方向**（而非一篇论文）梳理成一份概念 + 数学公式并重、
图文并茂、简洁不啰嗦的中文 `.md` 文档。核心价值：**公式严谨可核对，脉络清晰可复习**。

## 输出约定

- 文档用简体中文；术语、符号、方法名、指标名保留英文原词。
- 公式一律 LaTeX：行内 `$...$`，独立公式 `$$...$$`；重要公式编号便于引用。
- 文档默认写在当前工作目录（用户指定位置优先），**不写临时目录**。
- 文档名 `<主题短名>_概念梳理.md`；图片放同级 `<主题短名>_概念梳理.assets/` 目录，
  图片文件名用可读 ASCII 小写短名（如 `adam_update_rule.png`）。
- 所有图有图注（图 N + 说明 + 图源）、所有表有题注（表 N + 说明），格式见 doc-template.md。
- roadmap 落盘为同目录 `<主题短名>_概念梳理.roadmap.md`（提纲 + 公式抄录 + 来源）；
  交付后先保留供对照，用户确认任务完成后按工作流第 8 步清理。

## 边界

- 处理**方向/概念域**的梳理。单篇论文精读用 `paper-well-know`；
  多轮文献调研报告用 `academic-deep-research`。
- 不写代码实现教程、不做实验复现；伪代码/极短代码片段仅在帮助理解算法时使用。
- 公式和史实必须可查证：优先一手来源（原论文、教科书、官方文档）；
  博客/百科只帮助理解，不作为公式依据。
- 拿不准的内容：要么查证，要么显式标注"存疑"，要么删掉。**不许静默猜测。**

## 主题粒度分级

动笔前先判定粒度，决定深度：

| 粒度 | 例子 | 写法 |
|---|---|---|
| 单概念级 | 卷积、softmax、KL 散度 | 一个概念多角度深挖：定义、多种等价形式、完整推导、性质证明 |
| 方向级（默认） | 优化器、损失函数、位置编码 | 逐方法展开：概念/公式/推导/性质/优缺点/用途 + 对比表 |
| 领域级 | 机器学习、强化学习 | 总览 + 分支地图，每块只给核心公式与直觉，不做长推导；主动建议用户后续按分支深挖 |

主题过宽或含糊时，先向用户确认范围再动笔。

## 默认工作流

1. **界定范围**。确认主题、粒度（按上表）、目标读者深度（默认：有基础、要系统复习的研究者）、
   目标渲染器（默认 Typora/Obsidian；GitHub 场景按 doc-template.md 的兼容性约定降级）。
2. **联网调研 + 建 roadmap 并落盘**。先读 `references/roadmap-review.md` 的"构建"部分，
   用 WebSearch / 原论文 / 教科书建立主题 roadmap，**写成 roadmap 文件**：子概念清单、
   演变时间线、依赖关系、每个节点的一手来源与关键公式抄录。
   roadmap 既是提纲也是 review 对照物；**后续一切核对以该文件为准，不对模型记忆。**
3. **确定输出位置**，创建文档与 assets 目录。
4. **取图**（按顺序降级；论文原图可先批量取，自绘/codex 图允许写作中按需补，
   不必为走流程提前画）：
   1. 论文有 arXiv HTML 版（`https://arxiv.org/html/{id}`，备选 `https://ar5iv.org/abs/{id}`）
      → `curl -o` 直接下载 `<img>` 指向的图片；
   2. 只有 PDF → **直接从论文页面截取**（首选整页渲染 + 裁剪；`pdfimages` 抽嵌入图
      常把矢量图拆碎或漏图，仅作快速尝试）：
      `pdftoppm -png -r 200 -f N -l N paper.pdf page` 渲染目标页 →
      Read 看渲染图确认目标图位置 →
      `convert page-N.png -crop 宽x高+X偏移+Y偏移 +repage <fig短名>.png` 裁出图区域 →
      再 Read 裁剪结果确认无残缺/无越界；
   3. 以上都不可行 → 示意重绘：简单流程/关系图用 Mermaid / LaTeX；其余图先判断
      **主要表达目标**，不许把 matplotlib 当作通用默认：
      - 机制、信息流、空间关系、视觉隐喻等概念解释图 → 当前环境若提供已审核的生图工具，
        **必须先尝试真实调用**；把精确年份、公式、长标签移到图注，必要时拆图；
      - 定量曲线、坐标轴、公式标注、精确拓扑/文字等必须可核对的图 → matplotlib 脚本；
      - 同一主题兼有概念解释与定量比较 → 拆成 codex 生图 + matplotlib 两张图，不因其中
        一部分需要精确表达而把全部配图降级为 matplotlib。
      若全文存在适合概念生图的场景且当前环境提供生图工具，至少真实调用一次；只有按
      `references/codex-diagram.md` 重试后仍失败，才允许降级。调用方式、反造假校验与
      验证闭环见该文件；均标注"示意图，自绘"（codex 绘制的注明）。
   每张图（含截取裁剪图）下方必须标图源（论文名 + Fig 编号，或 URL）。
5. **增量写作 + 逐节核对**。先读 `references/doc-template.md`，按骨架逐节写；
   每节开头先写与上一节的衔接句（问题链），每个方法配落地例子（两条硬要求见 doc-template.md 第一节）；
   **每写完一个一级节点，立即对 roadmap 文件过一遍公式核对（review 清单 B 项）**，
   再写下一节。不许全文写完再统一补查。
6. **全局 review（硬门禁）**。按 `references/roadmap-review.md` 执行：全局项
   （覆盖度、史实、逻辑、成品质量）+ **独立视角公式复核**（环境支持时使用干净上下文的
   子代理逐条比对；否则重新载入来源，按独立清单做第二遍复核，方法见该文件第二节）。任何一项不过就修完从该项重查。
7. **交付说明**。按 roadmap-review.md 的"交付报告格式"输出：文档/图片/roadmap 路径、
   核对公式条数、独立复核与数值验证结果、存疑项；不把整篇文档复制进聊天。
   成品满意时，可建议用户把代表性章节回填本 skill 的 `examples/` 作范例（目录不存在则创建）。
8. **收尾清理（仅在用户明确说任务完成后执行，不许提前）**。交付后 roadmap 等中间产物先保留，
   供用户对照检查；等用户明确表示任务完成/满意时，删除与成品无关的中间产物：
   roadmap 文件、整页渲染图（`page-N.png` 等）、未被正文引用的裁剪残图与临时脚本。
   保留成品 `.md` 与 assets 目录中被正文引用的图片（及自绘图的生成脚本 `.py`）。
   删除前先列出待删清单再执行，删除后报告删了哪些文件；拿不准是否被引用的一律保留。

## 更新已有文档

输入是"已有概念梳理文档 + 增量需求"（如"在优化器文档里补上 Muon"）时，不走从零流程：

1. 先读原文档的符号表、编号体系、标注约定，**全部沿用**，不擅自重构已有章节。
2. 更新 roadmap 文件：加入新节点（来源、公式抄录、与已有节点的关系）；
   roadmap 文件不存在时，先从原文档反推重建一份再动笔。
3. 写新增节，图/表/公式编号续接原文档。
4. 同步更新受影响部分：对比表、总结/选型建议、参考资料。
5. review 范围 = 新增节（全套 B 项 + 独立复核）+ 受影响节（一致性）+ 全文编号/引用连续性；
   未受影响的章节不重查、不改动。

## 正确性规则（零容忍）

- **公式与一手来源核对**：每条关键公式能指出出处（论文 + 公式编号，或教科书章节）。
- **符号先定义后使用**：全文符号表统一，同一符号不重载。
- **每条公式过三个 sanity check**：量纲/形状一致、极限或特例退化正确、与相邻公式衔接无跳步。
- **推导每一步有依据**：出处编号，或标注"补充推导"。
- **史实（提出年份、作者、归属）逐条查证**，查不到就不写具体年份。
- 自己的直觉解释、补充说明一律用 `> 💡` / `> 📌 补充：` 标记，与可查证事实分开。
