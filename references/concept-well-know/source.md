# concept-well-know：概念与方向梳理参考

> 从本仓库 PR #2 的概念梳理 skill 改写。这里提供解释、组织与核对方法，唯一执行入口是根目录 [SKILL.md](../../SKILL.md)。不继承原作者的研究者身份、文档软件、配图习惯或强制工作流。来源见 [SOURCES.md](../../SOURCES.md)。

用于讲清概念的作用、机制、关系和适用条件。原参考围绕 LLM、Agent 与计算机概念，方法可用于其他主题；非数学主题不强加公式，非技术读者不假定已有研究基础。

## 按读者与问题选择深度

| 请求 | 写法 |
|---|---|
| 一句话 / 通俗解释 | 定义、关键作用和必要例子，直接在聊天回答 |
| 单概念机制 | 解释输入、变化和结果；有帮助时给公式、类比或小例子 |
| 多方法比较 | 按真正影响选择的维度比较；并列信息适合时用表格 |
| 系统梳理一个方向 | 按依赖、分类或对比组织，选择相关方法，不默认百科式穷举 |
| 领域总览 | 给分支与关系，深度服从篇幅；只在范围无法合理判断时询问 |
| 补充已有笔记 | 沿用现有符号、编号和语气，只改新增内容与受影响部分 |

信息足够就解释。长文才需要提纲，数学推导才需要相应核对；短回答不自动调研成报告，不创建 Markdown、图片目录或 roadmap。用户明确要最新信息、具体来源或材料存在不确定时，再按实际工具能力查证。

## 组织概念关系

先回答“它是什么、解决什么问题”，再补读者理解需要的前置概念。方法之间可能是依赖、并行路线、分类、不同表示或有出处支持的改进关系，不把所有方法写成上一方法的修补。

历史只在有助于当前理解时写；年份、提出者和“首次提出”回到原论文、教材或官方资料核对。综述可帮助建立地图，博客可用于发现线索；注明实际依据，不把二手解释包装成原论文结论。

示例应演示机制，而不是重复结论。可用数值、工程场景或贴近读者的生活类比，不限定每节一个或排斥生活类比；类比的边界影响理解时说明。

## 公式、性质与判断

- 使用公式时定义符号、形状与索引。短公式在正文定义即可，复杂文档可用符号表。
- 核对关键公式的来源、量纲或形状、条件与衔接。量纲检查不适用时换用相关检查，不把固定三项变成每条公式的门禁。
- 区分定义、恒等变换、近似、经验现象和定理。“实际常用”不等于“一定更优”，用户需要选型时给有依据的判断与适用条件。
- 补推导或直觉解释用自然语言标明身份，不要求固定 emoji 或颜色。
- 不为了统一符号改变原文含义；不同来源记号不同，可给映射并保持文内一致。

需要系统笔记时读 [doc-template.md](references/doc-template.md) 的相关部分；需要长文来源管理或数学核对时读 [roadmap-review.md](references/roadmap-review.md)；需要自绘图时读 [codex-diagram.md](references/codex-diagram.md)。这些资源分别按需读取，不要求一并加载或执行。

## 文档、配图与增量修改

用户要保存时按指定路径或项目现有布局写文件，没有布局时可在当前项目选清楚的文档名与配套图片目录。公式和强调兼容目标载体，不默认 Typora / Obsidian、`\tag`、HTML 颜色或固定主题。

图要回答一个问题。原图适合提供证据，Mermaid 或 HTML 组件适合流程关系，绘图脚本适合精确数据，生图适合视觉示意；按信息与工具选择，不因生图工具可用就强制调用。不编年份、曲线或数据来填图。

更新已有文档时先读符号、编号、来源与受影响段落，再补内容、对比和引用。存在来源笔记时同步更新；不存在时只建立本次必要的核对记录，不先重建整套 roadmap。验证新增与受影响内容，不重写无关章节。

聊天交付直接给解释；文件交付给成品链接和必要限制。核对方法按任务风险选用，不默认独立子代理、多模型辩论、二轮审查或统计报告。保留支撑成品的来源记录、图片与复现脚本，只清理本次无用的临时产物。
